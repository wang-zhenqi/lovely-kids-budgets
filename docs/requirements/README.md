# 需求

这里只放已经决定的产品意图。一篇正式需求一个文件，直接放在本目录，文件名用术语表里的名称。读者是 `leadership`，种类是 `explanation`。模板在技能 `knowledge-base` 的 `references/prd.md`。

开发要逐条验收时，在本目录另写一篇 `kind: reference`、`audience: developer` 的文档，并从正式需求链接过去。

本目录尚无正式需求。新增一篇时，把路径写进 `docs/INDEX.md` 里「产品决定做成什么样」那一行。

一句话需求、分析草稿和被拒绝的想法写在 `docs/inbox/`。决定采纳后，写入正式需求并删除那篇原料。决定拒绝后，直接删除，不留清单。

这里不记录代码现在怎样运行，也不保留设计说明或实现计划。
