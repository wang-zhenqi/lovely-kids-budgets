# 理论

这里记录儿童对金钱的经验，供设计正式需求时阅读。它不回答产品已经决定做成什么样，也不回答代码现在怎样运行。

- [如何记下理论](如何记下理论.md)：从一条碎片走到文章，再在改产品时写下决策记录。
- [fragments](fragments/README.md)：还不能当依据的单条记录。收进文章后删除。
- 文章直接放在本目录，文件名用问题，例如 `水位.md`。同一问题的第二篇碎片出现时再写文章，不预建空文章。

Agent 设计正式需求时，只打开被点名的文章。写代码时先读 `docs/decisions/` 里已接受的记录；记录链接了哪一节，再打开那一节。

自媒体稿从文章写出，不在这里再存一份。对外说法若改了主张，改文章；若产品因此要改，按教程新写一条决策记录。
